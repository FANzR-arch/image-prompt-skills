# Tech Schematic Poster（工程蓝图 / 赛博终端示意图编译器）

把一个概念编译成**一条**可直接交给图像模型的提示词，风格锁死为「技术示意图海报」：节点-连线拓扑图当主视觉，套一层 HUD 仪表框（角落数据面板、图例、标尺、系统日志）。

核心原则：**风格锁死，图即内容。** 这套风格不是加科技感滤镜，是把文章的逻辑结构本身画成一张工程图——节点是岗位，连线是交接，菱形是 fan-out/fan-in。结构越清楚，图越好看。

## 两种输出模式

| | 封面 Cover | 插图 Inline |
|---|---|---|
| 目标 | 首屏砸眼、可点击 | 讲清一个段落的结构 |
| 画幅（锁死） | **5:2 横板** | **16:9** |
| 主标题 | 巨型渲染进画面 | 极少量拉丁小标，或无 |
| 拓扑复杂度 | 完整菱形 + 具名节点 + 全套 HUD | 单一概念图，HUD 精简 |

## 两种色调寄存器（Register）

一次选一个，整篇统一，不混用：

- **TERMINAL（默认）**：纯黑底 + 单一霓虹绿荧光，等宽字，发光扫描线质感。赛博终端 / 系统监控 HUD 感。
- **BLUEPRINT（可选）**：宝蓝底 + 白色技术线，晒图纸质感，标尺、图例、标题栏。工程蓝图感。

用户没指定就用 TERMINAL。

## Read

- 编译提示词：读 `references/compile-contract.md`（消歧义铁律 + 锁死内核 + 固定骨架 + 两寄存器预设）。
- 要成品参考或批量做整篇：读 `references/examples.md`（封面 + 系列插图的已决策成品 prompt）。

## Input

从用户输入推断，不要求填表：

1. **模式**：封面（5:2）还是插图（16:9）。做整篇时先出封面再出插图系列。
2. **寄存器**：TERMINAL（默认）/ BLUEPRINT。
3. **主标题**：用户原文照抄，不翻译不润色；中文主标建议 2-8 字，最多一行小副标。只有封面渲染大标题。
4. **拓扑内容**：把段落逻辑转译成一张节点图——
   - fan-out（一个入口分出多个 Agent）
   - 菱形（分 → 并行 → 并 → 出）
   - 线性链 vs 并行（讲假依赖时）
   - 单节点自循环（讲 Loop 时）
   - 决策分叉（讲 Router / 判断清单时）

## Workflow

1. **判模式**：封面锁 5:2、插图锁 16:9。
2. **判寄存器**：默认 TERMINAL；用户说蓝图 / 图纸 / 蓝白就切 BLUEPRINT。
3. **选拓扑**：一张图一个主结构，对应段落的核心逻辑。抽象概念要落到具体拓扑（分工→菱形；假依赖→链条断开成并行；验收→带回环的循环）。
4. **锁招牌装置**：整篇封面 + 所有插图共享同一寄存器 + 同一套 HUD 框（角落面板 / 图例 / 标尺 / 日志）。只有中间的拓扑图和标题变，边框系统不变——这是整篇成系列的关键。
5. **编译提示词**：按 `compile-contract.md` 的固定骨架输出成品，无占位符、无菜单、正文零中文（渲染标题除外）。
6. **输出**：模式 + 寄存器 + 一条完整提示词 +（可选）一句选型理由。用户只要 prompt 时省略解释。

## Quality Gates

- 拓扑图是主视觉，HUD 是配角；不要让面板和日志抢过中央的节点图。
- 单一色相铁律：TERMINAL 只有一种绿，BLUEPRINT 只有蓝底白线 + 最多一个强调色。出现第二种彩色即偏移。
- 节点-连线关系必须读得出来：入口、并行分支、汇合、出口、回环，缩略图状态下结构不糊。
- 主标题精确渲染，中文标题用用户原文，不出现假中文字；次级小字用拉丁字段标签（NODE / EDGE / FAN-OUT / A1 / EXIT / [ok]）。
- 不生成看起来像真实可读代码的大段文字；日志和字段是短标签，不是真代码。
- 封面永远 5:2，插图永远 16:9，除非用户明确改画幅。
- 本 skill 只产出提示词，不编造已生成的图片结果。
