# Tech Schematic Poster（工程蓝图 / 赛博终端示意图编译器）

把一个概念编译成**一条**可直接交给图像模型的提示词，风格锁死为「技术示意图海报」：节点-连线拓扑图当主视觉，套一层 HUD 仪表框（角落数据面板、图例、标尺、系统状态行）。

核心原则：**风格锁死，图即内容。** 这套风格不是加科技感滤镜，是把文章的逻辑结构本身画成一张工程图——节点是岗位，连线是交接，菱形是 fan-out/fan-in。结构越清楚，图越好看。

## 两种输出模式

| | 封面 Cover | 插图 Inline |
|---|---|---|
| 目标 | 首屏砸眼、可点击 | 讲清一个段落的结构 |
| 画幅（锁死） | **5:2 横板** | **16:9** |
| 主标题 | 巨型渲染进画面 | 极少量拉丁小标，或无 |
| 拓扑复杂度 | 完整菱形 + 具名节点 + 全套 HUD | 单一概念图，HUD 精简 |

## 单一寄存器

纯黑底 + 单一霓虹绿荧光 + 等宽字，赛博终端 / 系统监控 HUD 感。整套只有这一个配色，没有备选。

> 蓝底白线的工程图纸已经拆成独立 skill：`engineering-blueprint-sheet`。那边是**印出来的纸**（线型分级、尺寸标注、标题栏、纸纹折痕），这边是**发光的屏**（等粗细线条、辉光、扫描线）。两边元素不互相借用——终端上不许有折痕，蓝图上不许有辉光。用户要蓝图就转过去，不要在这里调色。

## 屏幕质感强度

这套风格最容易翻车的地方是出成一张干净矢量流程图——干净、正确、没味道。质感层不是可选滤镜，是**必带的一段**，独立于内容存在：内容是平面线稿，质感是承载它的那块屏。

三档，一次选一档，**整篇统一**（封面和所有插图必须同档，否则并排看一眼就假）：

| 档位 | 给什么 | 加了什么 |
|---|---|---|
| CRT-01 CLEAN | 信息密度高的插图、超长标题封面 | 横向扫描线 + 辉光溢出 + 四角压暗 |
| **CRT-02 STANDARD（默认）** | 封面和大多数插图 | 上一档 + 荧光竖向颗粒 + 屏幕弧度 + 边缘虚焦 + 玻璃雾感 + 逐行明暗浮动 |
| CRT-03 DEGRADED | 只用于封面/单张大图，讲旧、遗留、故障、归档 | 上一档 + 横向刷新亮带 + 右向拖影 + 烧屏残影 + 雪花噪点 + 老化玻璃 |

用户没指定用 CRT-02。

铁律一条：**质感盖在内容之上，永远不吃内容**——扫描线压过标题和节点标签，但缩略图状态下所有字仍然认得出来。

## Read

- 编译提示词：读 `references/compile-contract.md`（消歧义铁律 + 锁死内核 + 固定骨架 + 三档质感层原文）。三档 SCREEN TEXTURE 的英文段落在那里，整段复制，不要自己重写。
- 要成品参考或批量做整篇：读 `references/examples.md`（封面 + 系列插图的已决策成品 prompt）。

## Input

从用户输入推断，不要求填表：

1. **模式**：封面（5:2）还是插图（16:9）。做整篇时先出封面再出插图系列。
2. **质感强度**：CRT-01 / CRT-02（默认）/ CRT-03。用户说「旧一点」「故障感」「年代感」就上 CRT-03，说「干净点」「太脏了」就退 CRT-01。
3. **主标题**：用户原文照抄，不翻译不润色；中文主标建议 2-8 字，最多一行小副标。只有封面渲染大标题。
4. **拓扑内容**：把段落逻辑转译成一张节点图——
   - fan-out（一个入口分出多个 Agent）
   - 菱形（分 → 并行 → 并 → 出）
   - 线性链 vs 并行（讲假依赖时）
   - 单节点自循环（讲 Loop 时）
   - 决策分叉（讲 Router / 判断清单时）

## Workflow

1. **判模式**：封面锁 5:2、插图锁 16:9。用户要的是图纸不是屏幕，转 `engineering-blueprint-sheet`。
2. **判质感档**：默认 CRT-02；整篇一档到底。
3. **选拓扑**：一张图一个主结构，对应段落的核心逻辑。抽象概念要落到具体拓扑（分工→菱形；假依赖→链条断开成并行；验收→带回环的循环）。
4. **锁招牌装置**：整篇封面 + 所有插图共享同一套 HUD 框（角落面板 / 图例 / 标尺 / 状态行）+ 同一档质感层。只有中间的拓扑图和标题变，边框和质感一字不变——这是整篇成系列的关键。交付成图时，再配一张已出好的基准图当参考一起喂，比只靠文字稳；后续每张都锚回那张基准图，不要拿上一轮输出继续改。
5. **编译提示词**：按 `compile-contract.md` 的固定骨架输出成品，无占位符、无菜单、正文零中文（渲染标题除外）；SCREEN TEXTURE 段整段照抄不改写。
6. **输出**：模式 + 质感档 + 一条完整提示词 +（可选）一句选型理由。用户只要 prompt 时省略解释。

## Quality Gates

- 拓扑图是主视觉，HUD 是配角；不要让面板和日志抢过中央的节点图。
- 单一色相铁律：只有一种绿，出现第二种彩色即偏移。**CRT 质感不是破例口子**——RGB 子像素三联点、色散分离、彩虹边一律不要，老屏幕在这里是单色荧光屏。
- 不许出现纸的元素：折痕、水渍、纸纹、图钉孔、线型分级、尺寸标注箭头、标题栏表格——那些属于 `engineering-blueprint-sheet`，出现即串味。这边**示意图线稿**全部一样粗，这是屏幕的语法；**这条只管线不管字**，标题该粗就粗，AVOID 要写成 `varying stroke weights inside the linework`。
- 质感层必带，且必须是独立一段；只在 LOCKED 里写一句 scanline 会被模型无视，出来还是干净矢量图。
- 质感不吃字：缩略图状态下主标题和所有节点标签仍然清晰。扫描线咬碎笔画、辉光把标题糊成一团光斑，都算废图。
- 节点-连线关系必须读得出来：入口、并行分支、汇合、出口、回环，缩略图状态下结构不糊。
- 主标题精确渲染，放引号里并补 `render verbatim, no extra words or characters`；中文标题用用户原文，不出现假中文字，字体走粗黑体（**不写 monospace**，那对中文无效）。次级小字用拉丁字段标签（NODE / EDGE / FAN-OUT / A1 / EXIT / [ok]）。
- 不生成看起来像真实可读代码的大段文字；状态行和字段是短标签，不是真代码，**也不带时间戳**（时间戳会诱发日期，和禁日期打架）。
- 封面永远 5:2，插图永远 16:9，除非用户明确改画幅。合法分辨率：5:2 → `2560×1024`，16:9 → `2560×1440`。画面有小字，quality 拉到 high。
- 本 skill 只产出提示词，不编造已生成的图片结果。
