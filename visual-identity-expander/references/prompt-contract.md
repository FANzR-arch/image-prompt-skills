# Prompt Contract

编译规则。风格由参考图决定，本文件只管**怎么写才是一条合法、自足、能复用的提示词**。

## 双锚原则（本 skill 的承重墙）

一条身份延展提示词有两种可能的身份锚点：

- **图锚点**：`Image 1: identity reference.` 靠参考图承载身份。保真度高，但**离开这张图就失效**。
- **文字锚点**：把参考图的身份特征写成自足的英文视觉描述。保真度低，但**可以存档、可以发给别人、以后还能用**。

**默认两个都写。** 文字锚点必写、写满；图锚点在参考图确实在生成上下文里时额外附加一行。这样同一条提示词带图时保真，脱离图时降级仍能出东西。

例外——用户明确说「我只要能直接出图」且图就在手上时，可以只走图锚点，但**必须提醒这组提示词不能存档复用**。

### 文字化的诚实边界

文字锚点的保真度按输入类型分级，交付时如实说，不要让用户以为文字能锁住一切：

| 输入 | 文字锚点能锁住 | 文字锚点锁不住 |
|---|---|---|
| Logo / 几何标识 | 几乎全部——比例、负空间、色值、字标关系都可量化 | 手绘笔触的随机细节 |
| 产品 / 物件 | 大部分——外形、结构、材质、配色 | 精确的模具曲面和真实品牌标 |
| IP / 插画角色 | 大部分——头身比、轮廓、配色、道具 | 画师笔法的个人特征 |
| 人物 / 真人头像 | 只能锁住**可识别的类型特征**（发型、眼镜、服装、气质、镜头习惯） | **同一张脸**。文字描述不可能锁定面部身份 |

人物类走纯文字锚点时，必须在输出顶部写明：这组提示词保的是**风格与形象一致**，不是**同一个人**。要同一张脸就必须带图生成。

## 七槽

对齐 `gpt-image-prompt-spec`。定序，可省略不可乱序。分段带标签写，正文英文，画面内文字按用户给的语言。

| 槽位 | 本 skill 里写什么 |
|---|---|
| Use case | 五类交付物之一：brand key visual / identity system board / variation sheet / application mockup / social scene |
| Scene | 环境、背景基底、时间氛围。识别板类写"平铺展示环境" |
| Subject | 主体 + **identity lock**：文字化的不可变特征，逐条点名 |
| Key details | 主辅色（给色值）、材质、光线、媒介、边缘处理、气质 |
| Composition | 机位、主体位置、留白、画幅、面板排列逻辑 |
| Text in image | 用户给的准确文字 + 字体规格 + 位置；没有就 `no text` |
| Constraints | `no X` 排除项 + `preserve X` 不变量 |

参数层不进正文：size（长边 <3840、双边 16 的倍数、比例 ≤3:1、总像素 655,360–8,294,400；>2560×1440 为实验档）、quality（成品 medium–high）。画幅同时写进 Composition，因为很多界面没有参数位。

图锚点写在 Subject 段首：`Image 1: identity reference — preserve the face, hairstyle and eyewear exactly.`

## 成组基座

五条提示词是**成组产出**。模型一次只看得见一条，共享规则不会自动继承。

**必须逐字写进每一条**的基座三段：

1. **identity lock**（Subject 段内）：不可变特征清单，一字不改地重复五遍。
2. **色板与材质**（Key details 段内）：主辅色值、媒介、光线性格。
3. **身份纪律**（Constraints 段内）：`preserve` 清单 + 身份漂移类排除项。

**只允许变**的：Use case、Scene 的情节部分、Composition、Text、以及跟当前载体相关的那部分排除项。

一致性靠基座重复实现，不靠事后逐张修。看到五条提示词里 identity lock 的措辞出现分叉，就是编译错了，回去统一。

## 五条硬规则

继承自 `gpt-image-prompt-spec`，逐条适用：

1. **不输出独立 `Negative prompt:` 块**——排除项写进 Constraints 正文。
2. **不用 seed / 权重 / `--` 参数**——迭代靠一轮只改一处 + `keep everything else the same`。
3. **不用水词**——masterpiece / 8k / ultra detailed 换成视觉事实（brushed aluminium、soft bounce light、matte uncoated stock）。
4. **画面文字**放引号、给字体规格与位置，加 `render all text verbatim, no extra words`。
5. **元信息不进正文**——"这是第三条""参考上一张"这类话留在文档层。

## 编译要求

- 成品里不留 `{}`、`[]`、斜杠菜单、either/or 或"可选择"。
- 不使用"同上一张""保持之前风格"等跨提示词省略——**跟成组基座是同一条规则的两面**。
- 用户没指定风格时，依据参考图作出一个明确决定，写进"本次假设"，不把决定权推回给模型。
- 五条共享同一组不可变特征，但构图和使用场景必须有明显区别。看不出区别就是同一条写了五遍。
- 文字不确定时优先减少文字数量，而不是编造。
